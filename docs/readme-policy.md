# READMEの編集方針

参考: [Oh My Openagent README](https://github.com/code-yeongyu/oh-my-openagent/blob/59d23b5c1ddc2a02210ede4cb485f88996fd02bd/README.md)。構成を参考にし、文章・広告・評価・成果の主張は転用しない。

## 書くこと

- 製品が解決する問題と、利用者が得る機能。
- 導入条件、実際に利用できる導入方法、最初の依頼の例。
- HardTackleの開始・状態確認・停止・再開。
- 担当の役割とモデル設定、結果回収と成果物確認。
- DSH Webの表示位置と、CLI／SDKとの違い。
- Dashboardとの関係、単独利用と同時利用。
- 必須と任意を区別した認証・追加ツールの案内。
- 設定、開発、ライセンス、問い合わせ先へのリンク。

## READMEに書かないこと

- 「ユーザー指定の名称」など、この開発依頼の会話や命名経緯。
- 担当者への弁明、承認履歴、過去の進捗報告、移植件数、試験件数、個別の実機検証経緯。検証証拠は独立した記録に置く。
- BoulderやAtlasなど、利用の説明に不要な内部識別子の羅列。
- 「全機能完全互換」「必ず完成」「すべてのモデル対応」など、根拠のない保証。
- 未実装のインストーラーや未公開のnpmパッケージを、利用可能であるように示すコマンド。
- このMac固有のパス、個人名、セッション、認証情報。
- 第三者の宣伝、利用企業、推薦文をScrumの実績として流用すること。
- OMOのコード・プロンプトをそのまま配布していると誤認させる表現、公式関係の示唆。
- 任意のAntigravity認証をScrum全体の必須条件として記述すること。

詳細仕様に必要な技術情報は実行リファレンスへ、検証結果は検証記録へ、出典と権利はNOTICEと対応表へ置く。利用者が判断を誤る制限はREADMEにも簡潔に記載する。
