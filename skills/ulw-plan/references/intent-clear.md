# Clear requested outcome

Write the final output and the observable completion condition first. Inspect the current application and its connected callers before selecting changes. Reuse existing state and retain user records. Identify concrete missing behavior and the evidence needed to accept it.

Break the implementation into output-producing tasks. Include dependencies, acceptance scenarios, regression checks and release steps when the request includes them. Record unknown external requirements separately; do not silently weaken the outcome. A task completion report must identify the changed artifact and verified behavior.

Proceed with authorized implementation. Avoid requesting approval again for already approved reversible work. If a required external action needs the user, finish the independent preparation first and identify the exact action and why it is required.
