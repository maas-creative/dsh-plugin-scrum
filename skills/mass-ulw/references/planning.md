# Plan a large workflow around outputs

Describe the final deliverable and evidence that would establish it. Split into tasks that produce usable, reviewable outputs; distinguish those tasks from projects that hold the overall outcome. Do not duplicate one outcome into several unrelated projects merely because multiple sessions discuss it.

For each task record identity, owner, inputs, dependencies, expected output, acceptance, allowed scope and recovery checkpoint. Make cross-task interfaces explicit before concurrent execution. Prefer a narrow vertical slice that proves the integration path before scaling out. Group work by dependency and ownership rather than filling a fixed number of slots.

Inspect resource capacity and the user's budget. Assign authorized workers only when parallel work can advance independent ready outputs. Preserve the fixed model and reasoning setting unless the user changes it. Ask about genuinely missing requirements while continuing independent work; do not make the user approve routine implementation decisions repeatedly.

Define aggregate review, integration, release and owned shutdown as real remaining work. Keep that state visible throughout execution. Plan updates should reflect newly discovered requirements and failed tests, not silently remove difficult acceptance criteria.
