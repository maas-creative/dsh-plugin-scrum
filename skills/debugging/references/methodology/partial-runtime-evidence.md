# State precisely what runtime evidence proves

A module import proves loading; a synthetic protocol fixture proves transport behavior for its programmed responses. Neither proves that a real debugger attached, a model executed a task, or a production integration succeeded. A successful process start does not establish successful initialization or resumption.

Record the observed boundary and its evidence: command, input, build, output, exit status and persisted state. Label synthetic inputs and mocked services. Explain which acceptance question remains unanswered and run the next available measurement. Retain failed cases alongside successes.

When only part of a workflow has been exercised, keep overall completion false. Do not replace a missing capability with an unrelated successful test. An external blocker must name the unavailable access or service and the alternatives already attempted.
