# Choosing a public API

Use the publisher's documented read API when it exposes the requested record. Confirm current documentation, account requirements and response semantics. Inspect the host tool catalogue before selecting a connector.

Constrain the query to the user's scope. Respect documented limits and backoff. Cache only permissible public data and keep retrieval time distinct from publication time. Prefer stable record IDs to display names.

An API can provide structured evidence without reproducing the browser page. Verify at least one returned record against its public detail page when a deadline, submission or financial decision depends on the mapping. If only the browser supports the required action, switch to the authorized connected browser explicitly.
